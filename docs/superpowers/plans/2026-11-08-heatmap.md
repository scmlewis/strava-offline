# Heatmap Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Strava-style personal heatmap tab that overlays every imported GPS route as a glowing density layer on a dark basemap, filtered by the existing toolbar and by sport chips.

**Architecture:** Pure geometry/sanitisation/colour logic lives in `src/data/heatmap.ts` and is unit-tested in Node. The view in `src/ui/heatmap-view.ts` draws all routes into an offscreen canvas once per filter change, blurs and colourises it, and hands the PNG blob to Leaflet as an `L.imageOverlay`; Leaflet owns pan/zoom. Tiles come from CARTO dark raster tiles and are cached by the existing Workbox service worker.

**Tech Stack:** TypeScript, Vite, vanilla DOM, Leaflet 1.9, uPlot-adjacent canvas 2D, Dexie/IndexedDB (read-only), Workbox via vite-plugin-pwa, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-heatmap-design.md`

## Global Constraints

- Routes stay decimated to the existing **max 120 points** per activity; no DB migration, no re-import, stored `Activity.route` is never modified.
- No network calls except CARTO basemap tiles. Tile URL: `https://{s}.basemaps.cartocdn.com/dark_all/{z}/{x}/{y}{r}.png`. Attribution: `&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors &copy; <a href="https://carto.com/attributions">CARTO</a>`.
- Preferences key is exactly `heatmapPrefs`; add it to `SETTINGS_KEYS` in `src/data/db.ts`.
- Unit tests run with Vitest `environment: 'node'` — no DOM, no canvas, no `localStorage`.
- All user-visible strings go through `t()` in `src/i18n.ts`.
- Leaflet is a static import: dependency `leaflet@^1.9.4`, dev dependency `@types/leaflet`.
- Dark basemap in both app themes.
- Do not add a backend, account, key, or upload path.

## Review Focus

1. **Malformed GPS data** — one `(0,0)`, `NaN`, or GPS-spike point must not drag the heat bounds to world scale. Owned by Task 1 (`sanitizeRoutes` tests).
2. **Offline / blocked tiles** — the heat layer must still render on the dark field, with one quiet note and no error screen. Owned by Task 4 (e2e with all `cartocdn` requests aborted).
3. **Filter moves the data to another region** — the map must refit instead of leaving the user on an empty basemap; a chip-only change must keep the view. Owned by Task 5 (`shouldRefit` tests + e2e).
4. **Repeated tab/filter switches** — no leaked Leaflet maps, overlays, or blob URLs; at most one `.leaflet-container` in the DOM. Owned by Task 5 (e2e).
5. **CSV-only history** — no routes means panel + hint, never a broken map. Owned by Task 3 (e2e empty state).

- [ ] **Step 3: Implement the module**

Create `src/data/heatmap.ts` with the exports listed above. Use these exact maths:

- `lonLatToWorld`: `x = (lon + 180) / 360`; `y = 0.5 - Math.log((1 + sin) / (1 - sin)) / (4 * Math.PI)` where `sin = Math.sin(lat * Math.PI / 180)`.
- `worldToLonLat`: `lon = x * 360 - 180`; `lat = (180 / Math.PI) * Math.atan(Math.sinh(Math.PI * (1 - 2 * y)))`.
- `haversineKm`: standard great-circle distance with `R = 6371`.
- `sanitizeRoutes`: keep points where both coords are finite, not exactly `(0, 0)`, and `Math.abs(lat) <= 85`; compute the per-activity median lat and lon; drop the activity if its median is within `0.001` of `(0, 0)`; drop points farther than `MAX_POINT_RADIUS_KM` from that median; keep the activity only if at least 2 points remain. Push `{ id: a.id, type: (a.type || '').trim() || 'Unknown', points }`. Return new arrays; never mutate inputs.
- `computeHeatBounds`: min/max lat/lon over all points; expand each axis to at least `MIN_SPAN_DEG` around its centre; pad both axes by `padFraction * span` (default `0.04`); return `null` for no points.
- `sportTypes`: derive from `sanitizeRoutes(acts)` (so a chip only appears when that sport has a route that will actually render), normalise each type with `(type || '').trim() || 'Unknown'`, then sort by count descending and `localeCompare` ascending. This makes the empty-`type` test case count as `Unknown` and keeps the counts consistent with the heat layer.
